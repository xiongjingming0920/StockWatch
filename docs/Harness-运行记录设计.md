# Harness 第一阶段：任务与运行记录

本阶段为本机生鲜缺货巡检助手的每次对话请求添加运行记录。它解决的是“这次运行发生了什么、在哪一步失败”，不是任务排队、取消或断点恢复。通用 CSV/TXT 对话暂未接入。

## 一次运行的路径

```text
已登录用户提交个案问题
    ↓
创建 run_id，写入 running 和 run_started 事件
    ↓
调用模型、执行受控工具、必要时规则降级
    ↓
按顺序写入步骤事件（状态、工具名、耗时和错误类别）
    ↓
写入 succeeded、degraded 或 failed 终态和 run_finished
    ↓
响应返回 run_id；用户展开“查看运行过程”时读取事件
```

`run` 是一次请求对应的运行记录，`event` 是运行中发生的一个步骤；同一工具可以产生多条事件，按序号区分。历史对话与运行记录是两种不同数据：对话文本仍由浏览器保存，运行记录写在本机 SQLite 中。

## 状态含义

| 状态 | 含义 |
| --- | --- |
| `running` | 已开始，尚未写入终态 |
| `succeeded` | 已按正常路径结束；这不是对模型回答正确性的判定 |
| `degraded` | 主路径未完成，执行了规则等降级路径 |
| `failed` | 运行失败，不能按正常或降级结果完成 |

结束状态和结束事件在同一数据库事务中写入。进程意外退出时，记录可能停在 `running`；第一阶段不自动将其判为失败，也不能恢复这次执行。后续需要单独设计中断检测与恢复。

## 存储、权限与隐私

- 默认文件：`backend/data/agent-runs.sqlite3`；测试和离线评测使用隔离的临时数据库。
- 运行事件按任务 ID 和单调递增序号保存；终态写入后不能继续追加事件。
- `GET /api/v1/runs/{run_id}` 只向当前已认证的记录所属用户返回记录，其他用户得到 404；此接口仍受本机管理员权限检查。
- 事件元数据使用固定白名单。第一阶段不保存用户问题、文件内容、工具参数、模型回答、API 密钥和原始异常文本；这也意味着仅凭运行记录不能完整重放请求或核验业务答案。
- 现有对话响应的 `evidence` 仍按工具名保存，同一个工具多次调用时，较早的工具结果可能被后一次覆盖。运行事件会保留每次调用的独立记录，但并不包含每次调用的参数和结果；完整证据链将在后续工具执行层设计中解决。
- 删除浏览器对话不会自动删除服务端运行记录；本阶段尚无记录保留期限或管理界面。SQLite 文件包含用户 ID 与个案 ID 等元信息，应与其他本机数据一样妥善保管。

## 如何体验

启动工作台，进入“生鲜缺货巡检”，生成清单、选择一个个案并向巡检助手提问。在该条新回复下展开“查看运行过程”。以前产生的回复没有运行 ID，不会凭空补齐旧轨迹。通用数据分析对话还没有这个入口。

## 本阶段如何验证

使用临时数据库和模拟模型/工具，检查正常完成、模型失败后的降级、异常终态、连续调用同名工具、事件顺序、访问隔离和敏感内容不进入日志。已有离线业务评测仍禁用真实模型；自动测试不会证明线上模型行为或服务稳定性。

## 下一阶段

优先将分散的工具调用与参数校验统一为工具注册与执行入口，再增加任务级预算、可靠的取消与恢复；不将当前实现描述为完整的 Agent Harness。
